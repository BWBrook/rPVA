# Practical 1 Barry-As-Student Roleplay Script

Use this script when Barry is ready to roleplay a Practical 1 student. For a
two-route test, choose the route and stop rules first from
`practical-1-dual-route-roleplay-runbook.md`. The aim is to test the student
experience, not to debug or improve the app during the session.

## Role

Act as a student who has received the Practical 1 Moodle section and app link.

Do not switch into instructor or developer mode during the run. If something
blocks progress, record the issue in the notes template and stop or follow the
fallback instruction exactly as a student would.

## Open

Open these items before starting:

- `practical-1-student-launch-page.md`
- `practical-1-mission-worksheet.md`
- the approved Practical 1 app route supplied for this roleplay
- `practical-1-roleplay-notes-template.md`

Create a local folder called `practical-1-evidence` for app downloads and any
fallback notes.

## Do

1. Read only the launch page instructions needed to start.
2. Open the approved Practical 1 app route.
3. Click `Start baseline`.
4. Inspect baseline run 1. Write one short note if anything is unclear.
5. In Concept Lab, run `Carrying capacity`.
6. Run one stochasticity mission, preferably `Environmental stochasticity`.
7. Run one risk-pressure mission, preferably `Catastrophe`.
8. Run one final comparison mission, preferably `Simple intervention`.
9. Open Compare.
10. Check that baseline run 1 and later runs are visible.
11. Download the comparison CSV.
12. Download the evidence-notes Markdown file.
13. Open the worksheet evidence-recording section and note the saved filenames.
14. Open Transfer and answer the prompts mentally or in brief notes.

## Pause And Note

Use the notes template at these points:

- after opening the launch page and worksheet;
- after clicking `Start baseline`;
- after the first changed mission run;
- after saving both evidence files;
- after reaching Transfer.

One sentence or a few keywords is enough.

## Evidence Expected At The End

The evidence folder should contain:

- `practical1-comparison-YYYYMMDD.csv`
- `practical1-evidence-notes-YYYYMMDD.md`

The worksheet or notes should record:

- one change made;
- one output that moved;
- one caveat or uncertainty;
- any point where the instructions slowed you down.

## Stop Conditions

Stop and record the blocker if:

- the app route is not supplied or does not open after one retry;
- login or access friction prevents acting like a student;
- a mission instruction is unclear enough that you would ask a demonstrator;
- Compare does not show the expected runs;
- either evidence download fails after one retry;
- you find yourself needing instructor or developer knowledge to continue.
